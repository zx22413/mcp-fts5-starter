## Summary

BM25 is the ranking function FTS5 uses by default. It scores a document
against a query by combining term frequency, inverse document frequency,
and document length normalization.

## Per-column weighting

FTS5's `bm25(table, w1, w2, ...)` accepts a weight per indexed column.
This is the single most useful knob for relevance tuning: a hit in
`title` is almost always a stronger signal than the same hit in `content`,
so you weight title higher.

The starter's default is `0, 10, 5, 1, 8, 0, 0`, meaning:

- `path`, `type`, `created`: weight 0 (don't participate in ranking).
- `title`: weight 10 (strongest signal).
- `tags`: weight 8 (curated metadata; less than title only because tags
  tend to be short and many).
- `summary`: weight 5.
- `content`: weight 1 (the long-tail signal).

## Tuning advice

If you have evaluation data, treat these weights as hyperparameters and
sweep them. If you don't, start with the defaults and only adjust when a
specific failure mode appears in real queries — for instance, raising the
`tags` weight if folksonomy hits are too far down the list.

## Score sign

BM25 returns *negative* scores in FTS5 — smaller (more negative) is better.
`ORDER BY rank` works correctly without an explicit `DESC`, which catches
people off guard the first time.
